# Implementation Plan

移設対象は `spawn_test_app` 呼び出し **203 箇所 / 20 ファイル**。うち `src/statuses/render_assembler/tests.rs` の 13 箇所は設計時点で Tier 2（例外）と判明しているため移設タスクを持たず、記録のみ行う。実際に移設するのは **190 箇所 / 19 ファイル**。

各移設タスクの共通手順は design.md「1 ファイル分の移設手順」に従う。可視性の壁に当たったら design.md「可視性の梯子」で段を判定し、Tier 2 と判定したテストは移設せず例外として記録する。

全移設タスクに共通する制約:

- 移設先ファイル名は `_it.rs` サフィックスで `tests/` 直下に置く（要件 1.3）
- テスト関数の対象・入力・アサーションを変更しない。削除・`#[ignore]` 付与・アサーション削減を行わない（要件 2.1, 2.2）
- 移設前に、同じモジュールを対象とする既存の `tests/*_it.rs` を確認し、重複する検証を新たに作らないこと（要件 2.4）
- 移設元に残った純粋な単体テストが引き続き通ること

## Implementation Notes

- 1.1: `src/test_harness/tests.rs` の「5 箇所」のうち L2 は `//!` ドキュメントコメント内の記述で、コード上の呼び出しは 4 箇所。対象 203 は不変（208−5 = 207−4）。要件 1.1 の完了判定は **grep 基準の 5** で行うこと。タスク 8.1/8.2 で内訳を明記する
- 1.1: design.md「File Structure Plan」の移設先名 19 件のうち **`tests/timelines_endpoints_it.rs` のみ既存ファイル（1341 行）と衝突**。既存は `kawasemi::server::build_router` の実ルータ、移設元 `src/timelines/endpoints/tests.rs` は手組みのテスト専用ルータを対象としており、タスク 7.2 は改名前に要件 2.4 の重複判定を行うこと
- 1.1: 要件 2.6 のテスト関数総数は、コメント・文字列をマスクした値で比較する（生 grep は doc コメント内の `#[tokio::test]` を拾う）。移設前 src 1779 / tests 507、移設後の期待値 src 1589 / tests 697、合計 2286 不変
- 2.2: **【方針確定・以降の波に適用】移設でテスト関数が 0 本になった `tests.rs` は削除し、`#[cfg(test)] mod tests;` の宣言も外す。** 移設先へのポインタは**本番モジュール自身の `//!` doc** に畳み込む。理由: (1) `#[cfg(test)]` 配下の `//!` は `cargo doc` に描画されないので案内板として機能しない、(2) design.md「変更ファイル」の「移設元ファイルのモジュール doc に移設先を記す」は本番モジュール側と読むのが自然、(3) steering はテストの無いモジュールに `tests.rs` を置けとは定めておらず、「`tests.rs` があるなら単体テストがある」という不変条件を保てる、(4) **スタブ doc に `spawn_test_app(` と書いた瞬間 8.4 の計数照合が黙って狂う**（`src/test_harness/tests.rs` L2 が実例）。`src/federation/outbound/worker/tests.rs` に適用済み
- 2.2: design.md 表の過大計上が 2 例目（`parse_acct_resource`）。逆に**表にない阻害要因**も出た（非公開 const `JRD_MEDIA_TYPE`。Tier 0 で解決、値は本番と一致を確認）。8.2 は表の訂正と追加の両方を記録すること
- 2.2: **8.4 の相互参照掃除は改行を潰してから検索すること。** `tests/webfinger_nodeinfo_it.rs:22-23` は移設元パスが行をまたいで折り返されており行単位 grep で検出できない。同 L45 の `src/federation/endpoints/*/tests.rs` もグロブ表記ですり抜ける
